# Motives Modeling - 业务建模指导 Skill

一个用于 AI 辅助代码编辑器（如 Trae、Cursor 等）的业务建模指导 Skill，帮助开发者评审和优化实体/表/属性设计，确保属性拆分合理、避免过度设计。

## 功能特性

- **模型评审**：对现有实体类、数据库表、枚举定义进行全面评审
- **属性分析**：分析属性拆分是否合理，识别设计问题
- **评分输出**：从属性设计、内聚性、生命周期、组合合理性、复杂度平衡五个维度量化评分
- **改进建议**：提供优先级明确的改进建议和判定依据
- **防过度设计**：通过复杂度测算，在"绝对纯洁"和"刚刚好的妥协"之间找平衡

## 安装

将本项目克隆或下载到你的 Skills 目录：

```bash
git clone https://github.com/your-username/motives-modeling.git
```

或在 Trae 中直接导入 Skill。

## 核心准则

本项目基于十条建模铁律进行评审：

| 序号 | 准则 | 说明 |
|------|------|------|
| 1 | 六域正交 | 属性归属严格限定于身份上下文、需求、计划、执行、结果、约束六个域 |
| 2 | 异空必拆维 | 不同业务子空间的生命周期正交，按空间拆分独立枚举 |
| 3 | 并发取积 | 同空间内状态并发时，拆为多维独立枚举取笛卡尔积 |
| 4 | 状态互斥穷尽 | 同空间单维枚举取值绝对互斥且完全穷尽 |
| 5 | 时序事实追加 | 结果域数据强绑定时间戳绝对不可变 |
| 6 | 意图实现解耦 | 计划域锁定目标契约，执行域承载易变细节 |
| 7 | 约束显式化 | 业务规则脱离代码控制流，沉淀为独立规约 |
| 8 | 类型极简降级 | 属性类型穷尽至基础数据类型或值对象 |
| 9 | 流转闭环兜底 | 状态机必含单一起始态与可达终态 |
| 10 | 上下文绝缘 | 同名词不同业务域必须物理或逻辑隔离 |

## 七条判定

用于判断属性是否需要拆分：

| 序号 | 判定条件 |
|------|---------|
| 1 | 说的是不同的事（异语义） |
| 2 | 流转规则不一样（异规则） |
| 3 | 不同人看不同的（异角色） |
| 4 | 进行中 + 已结束混一起（异时态） |
| 5 | 加新值影响其他逻辑（牵连扩缩） |
| 6 | 数据来源不同（异来源） |
| 7 | 更新频率差异大（异频率） |

## 案例演示

### 正面案例

订单状态：待支付、已支付、已发货。

| 判定 | 结论 |
|------|------|
| 六域归属？ | 都是交易流程（结果域） |
| 命中十条铁律？ | 无命中 → 不拆 |
| 复杂度测算？ | 单维枚举，复杂度低 → 合并 |

**结果**：`trade_status`：待支付、已支付、已发货

### 反面案例

错误设计：`execution_process: 未执行|执行中` + `is_completed: true/false`

| 判定 | 结论 |
|------|------|
| 六域归属？ | 都是执行进度（结果域） |
| 命中十条铁律？ | 铁律4：同一空间拆成两枚举，违背状态互斥穷尽 |
| 复杂度测算？ | 拆分增加复杂度 → 合并 |

**正确**：`execution_status`：未执行、执行中、已完成
